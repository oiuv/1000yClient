# 1000ySetup PC 客户端与素材源

本仓库管理标准 PC 客户端分发文件，同时作为 OSS 更新的本地源和相邻
`1000yAPP` 的 PC 原始素材源，使用独立 Git 仓库管理，主分支为 `main`。

## 文件与用途

- `Client.exe` 为游戏主程序；地图、图集、动作、界面、音效等原始素材保持现有目录与文件名。
- `cl1000.exe` 为云端 OSS 更新器，内置正式更新源和验签公钥，无需额外 INI。
- `cl1000CN.exe` 是内容相同的备用入口；台服更新覆盖 `cl1000.exe` 后，运行它可恢复本服主更新器和文件。两份云端更新器一同更新，备用入口也支持自更新。
- `cl1000TW.exe` 为台服更新器；`CPatch.ini` 保存其台服更新地址和通道。
- `ClientIni.ini`、`config/defcfg.ini` 是分发默认模板；个人截图、角色配置、更新状态和缓存不入库。

## 更新发布

1. 在本仓库替换或新增正式分发文件，核对 `git status` 和具体差异。
2. 使用相邻 `1000ySource/py1000y/patch/publish.py` 发布：脚本先在本目录从 `cl1000.exe` 自动同步 `cl1000CN.exe`，再生成新的发布快照、清单及签名。
3. 核对后先上传资源，再上传签名清单，最后做线上检查；Git 提交不等于 OSS 已同步。

发布配置与生产私钥由更新器维护仓库单独保存，不能复制到这里。发布扫描固定
排除 `.git`、Git 规则、维护文档和玩家运行数据。`CPatch.ini` 保留台服更新参数，
按普通受管文件纳入云端签名清单，本地修改或缺失时恢复。该文件供台服更新器读取
连接参数，云端更新器使用自身内置或 `cl1000.ini` 指定的更新源。

## APP 素材提取

在相邻 `1000yAPP` 中通过现有入口只读提取：

```powershell
python tools/prepare_assets.py --resource-dir '..\1000ySetup' --output 'build\assets-new'
python tools/prepare_assets.py --check --output 'build\assets-new'
```

APP 的派生图片、音频、图集和构建缓存保留在 APP 自身目录，不写回本仓库。
文件别名、解析规则与来源哈希以 APP 的资源工具及规范为准；变更素材后须重新导出
并核对新素材。

## 维护注意

原始二进制和 GBK／ANSI 文本按字节保存，不批量转码或格式化。部分文件原本为
硬链接，直接原地写入可能影响其它客户端；编辑前应先用独立副本替换对应文件。
仅在独立客户端副本中做启动和更新验收。
